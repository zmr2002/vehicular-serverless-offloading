# Optimization and result-gap report

## Scope

The thesis-fixed DQN shape (`20 -> 256 -> 128 -> 3`), three actions, maximum three V2V hops, task compute/data ranges, deadlines, and five named strategies remain intact. Parameters not fixed by the thesis are explicit in configuration. The corrected legacy six-station layout remains in `paper.toml`; new experiments use the separately reviewable `paper-improved.toml`.

## Performance changes

The original single-seed 2,000-step, 1,000-vehicle runs took approximately 479–807 seconds per strategy. Profiling showed that repeated service-quote scans and dense multi-hop expansion dominated runtime. The corrected implementation now uses:

- a lazily materialized spatial radius graph;
- direct-service lower bounds and bounded deterministic Dijkstra search;
- cached reverse reachability for sparse service sets;
- a single service-quote map per step;
- one cached SUMO mobility trace shared by all strategies;
- DQN optimizer interval 32 in the improved profile, with epsilon decayed per decision rather than per optimizer update. The final profile uses one intra-op thread because the screening run was 23% faster than 16 threads at 4,000 vehicles with the same success rate.

On seed 11 with 1,000 vehicles and 1,000 steps, measured core times were about 4.7–4.8 seconds for Random/Greedy/Stackelberg, 20.2 seconds for DQN, and 17.2 seconds for Hybrid. A 250-step Hybrid density smoke test took 4.8 seconds at 2,000 configured vehicles and 11.7 seconds at 4,000, with no dense-graph blow-up.

The simulator Docker image now installs CPU-only PyTorch. Its measured local image size fell from about 3.34 GB to 441 MB, while the independently built task-function image remains about 50 MB.

## Base-station placement

The old code's six stations are a 3-by-2 grid. An earlier reconstructed configuration mistakenly contained only three unrelated points. The baseline six points were restored first.

For the improved profile, six centers were calibrated by deterministic multi-start k-means on an independent 1,000-step seed-42 mobility trace, using only vehicle positions. On the seed-11 evaluation trace, mean nearest-station distance fell from about 271 m to 135 m and the 95th percentile from 389 m to 257 m. The full calibration evidence is generated by `scripts/optimize-base-stations.py`; success or reward was not used to choose positions.

## Algorithm changes

- Replay transitions connect one decision to the next actual decision state instead of duplicating a same-step state.
- Feasible-action masks apply during exploration and masked Double-DQN target calculation.
- Huber loss and gradient clipping improve training stability.
- Deadline shielding prevents avoidable timeouts. If every action is late, reviewed mode keeps every physically feasible action; it no longer forces a minimum-lateness destination that can waste shared cloud capacity.
- Stackelberg objectives normalize delay, energy, and payment before applying configured weights. Improved mode closes the thesis's unspecified cloud-demand relation with a bounded, smoothed, capacity-aware leader best response; congestion is part of the publicly paid price rather than a hidden social cost.
- The cloud price and service quotes are fixed before a step's task vehicles act. Every vehicle decides from the same state snapshot, and the complete batch enters queues only afterward.
- The DQN is a parameter-shared independent learner: replay links successive decisions of the same vehicle and the reward is private. Hybrid advances epsilon once per environment decision, including decisions resolved by the rule layer. The reviewed replay buffer preserves low, medium, near-capacity, and overloaded cloud states.
- Residual Hybrid decisions compare immediate private-reward advantage with a conservative advantage supported by both online and target networks. This lets DQN improve the game prior without silently turning the model into a centralized social planner.
- Local, V2V, and V2I energy coefficients are configured explicitly. V2I now includes both radio transmission and cloud-computation energy as required by the thesis equation.
- Analytical Serverless queueing accounts for concurrency target and bounded scale-out; cold-start estimation and execution use one backend state.
- V2V and V2I throughput now has explicit units: MHz is multiplied by Shannon spectral efficiency and a link-specific resource-efficiency factor. Distance enters once through the corrected log-distance SNR model rather than through a second ad-hoc bandwidth multiplier.
- Real HTTP V2I requests from the same simulation step execute concurrently. End-to-end HTTP delay already contains platform activation, routing, queueing, and processing, so no analytical cold-start constant is added to it.

## Corrected mathematical ceiling

The earlier low-to-mid 60% ceiling was not a property of the thesis workload. It came from a reconstruction error that treated the distance-adjusted 200 Mbps V2I value as final capacity and omitted the thesis Shannon/SNR multiplier. The legacy program and thesis prose both use `B_eff log2(1 + SNR)`.

With reference SNR 30 dB, V2I path-loss exponent 3.0, and the independently calibrated six-station layout, a representative 135 m V2I link has spectral efficiency about 7.85 and capacity about 1.53 Gbps. Before queueing, the mathematical success ceiling is therefore close to 100%, not 63%.

Short seed-11 checks with the unchanged workload support this correction. At 4,000 configured vehicles, Stackelberg achieved 98.25% over 250 steps and its oracle was the same; over 500 steps, density and analytical queueing reduced both to 92.24%. These are diagnostic runs, not final results, but they show that the thesis-reported 81%–86% range is physically attainable without changing task sizes or deadlines.

The first 500-step improved-profile screen at 4,000 vehicles reached 90.52%, but Hybrid delegated only 2.8% of decisions to DQN and remained below Stackelberg. The cause was twofold: epsilon decayed only on delegated decisions, and all-late tasks were sent to the fastest still-failing V2I action, consuming cloud capacity without increasing current success.

The corrected seed-11 fusion screen reaches 94.6931%, exactly matching both Stackelberg and its recorded oracle ceiling. Hybrid's V2V and V2I success rates are 100%, its avoidable-failure rate is zero, and successful-task latency is 0.61513 seconds versus Stackelberg's 0.61532 seconds. Under this fixed task stream and physical model, success cannot exceed 94.6931% without changing feasibility assumptions; Hybrid is therefore no longer weaker on success and slightly improves latency among successful tasks.

Deadline masking is a standard feasible-action projection and Stackelberg candidate guidance directly implements the thesis's stated Hybrid split. They are reasonable refinements rather than a new problem formulation. Their behavioral impact is nevertheless material, so `paper.toml` keeps the literal baseline and `paper-improved.toml` remains a separately labelled improved algorithm.

The result sweep now varies only thesis-unspecified numerical assumptions: V2V base bandwidth, reference SNR, V2V path-loss exponent, and maximum analytical cloud scale. It no longer uses payload reduction or compression as the primary route to matching the legacy table. Final comparisons should use `avg_success_latency_s`; the legacy code computed latency only over successful tasks, whereas `avg_latency_s` includes timeouts.
